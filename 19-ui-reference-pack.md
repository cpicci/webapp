# UI Reference Pack

## Purpose
This pack gives the webapp fresh start a concrete structural target.

The goal is not to imitate a real-estate product. The goal is to borrow the right product grammar for an operator workspace: queue first, detail nearby, support secondary, personal shell visible.

## Selection Rules
- structure first
- operator workflow first
- support kept secondary
- no dashboard walls
- no generic admin template logic

## Reference 1: Linear
- Link: https://linear.app
- Why it matters: Linear is excellent at shell discipline, hierarchy, and quiet confidence. It feels like a tool, not a dashboard.
- Keep:
  - restrained shell
  - strong vertical hierarchy
  - calm density
  - interfaces that feel operational instead of decorative
- Reject:
  - product language that is too software-team-specific
  - excessive abstraction around cycles and roadmaps
- Translate for Central Parc Immo:
  - use Linear as a reference for chrome, spacing, and confidence
  - not as a model for workflow terminology

## Reference 2: Front
- Link: https://front.com
- Why it matters: Front shows how a team inbox can become a work surface instead of a reporting page.
- Keep:
  - clear queue logic
  - prioritization through list structure, not through KPI overload
  - team-ready inbox ergonomics
- Reject:
  - messaging-first metaphors when they stop fitting dossiers and relances
- Translate for Central Parc Immo:
  - use Front as a reference for the left-column work queue and operator rhythm

## Reference 3: Missive
- Link: https://missiveapp.com
- Why it matters: Missive is useful for understanding how a shared inbox can feel like a command center without turning into a dashboard.
- Keep:
  - personal plus team context in the shell
  - command-center feeling through workflow, not through widgets
  - readable list-to-detail transitions
- Reject:
  - mail-heavy conventions that would make the product feel like a generic mailbox clone
- Translate for Central Parc Immo:
  - use Missive to inform the personal shell and the queue-to-detail relationship

## Reference 4: Intercom Inbox
- Link: https://www.intercom.com/help/en/articles/440-basic-information-about-inbox
- Why it matters: Intercom is strong at contextual support around the active conversation or case.
- Keep:
  - context attached to the selected item
  - support modules that live around the active work instead of defining the whole page
  - clear future room for assistant-like augmentation inside the workflow
- Reject:
  - customer-support branding cues that would make the product feel SaaS-support-first
- Translate for Central Parc Immo:
  - use Intercom as a model for detail-side support, not as a full visual model

## Reference 5: Notion Mail
- Link: https://www.notion.com/product/mail
- Why it matters: Notion Mail shows a more personal shell and a gentler, more editorial way to combine a queue with side context.
- Keep:
  - personal application feel
  - side context that feels integrated instead of bolted on
  - calm product voice
- Reject:
  - overly soft consumer-product cues if they weaken agency credibility
- Translate for Central Parc Immo:
  - use Notion Mail as a guide for the personal shell and the detail pane mood

## Reference 6: Onbox by Attio
- Link: https://attio.com/blog/introducing-onbox
- Why it matters: Onbox is the closest reference for handling many small cases quickly without constant context switching.
- Keep:
  - sequence-of-work logic
  - quick understanding of what needs handling next
  - reduced context switching through nearby detail
- Reject:
  - product assumptions tied too closely to CRM workflows
- Translate for Central Parc Immo:
  - use Onbox as a reference for handling many dossiers and relances as small operational units

## Synthesis
The recommended direction is not a dashboard and not a luxury admin panel.

It is a blend of:
- Linear for shell discipline and hierarchy
- Front for queue prioritization
- Missive for inbox-as-command-center behavior
- Intercom for context attached to the active item
- Notion Mail for personal shell and side-pane tone
- Onbox for handling many small cases without losing flow

## Explicit Rejections
Do not return to:
- BI dashboards
- generic admin templates
- visible `coming soon` AI or assistant blocks
- stacked cards as the dominant page grammar
- support modules that compete with the work queue
